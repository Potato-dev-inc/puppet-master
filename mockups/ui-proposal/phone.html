Phone PWA, proposal

Clickable mock of the phone view. Every agent, question and output is Example data; nothing connects to a PC. Tap around the phone, or jump to a state:

What changes, and why

  1. Bottom tab bar instead of a top strip. Thumb reach; the top strip scrolled sideways and hid agents. Inventory 3.3: tab strip with horizontal scroll at the top.
  2. Inbox ranks agents that need you first. Yellow count on the Inbox tab. Inventory 3.4: only an amber border marks a waiting agent.
  3. The card shows the actual question, with Yes / No / Open. Answer without opening the terminal. Inventory 3.4: the question is not shown on the card.
  4. One state dot everywhere, one vocabulary. Same colours on tabs, cards and headers. Inventory 6: the dot means connection on All, status on agent tabs.
  5. Offline is a labelled strip and disables answers. Inventory 6: phone offline state is only a small dot.
  6. Compact glass agent header, no pid. Name, project, state chip and size only. Inventory 6: the phone shows cols×rows · pid to end users.
  7. Pending-prompt banner above the input when the agent waits. Yes, No and a shortcut to Keys for menus. Inventory 3.5: nothing marks a prompt inside the feed.
  8. Keys is a labelled glass sheet. Words replace the keyboard glyph; same groups. Inventory 6: the Keys glyph suggests the OS keyboard.
  9. Jump-to-bottom sits above the composer. It no longer collides with the Keys control. Inventory 5, bug 8.
  10. Sheets have a grab handle and swipe-down. New-agent options show why a type is disabled; warm agents are badged. Inventory 3.6: no grab handle, no swipe-down, disabled reasons hidden.
  11. Unpair asks first, in-app. No native confirm(). Inventory 3.1 and 6: Unpair has no confirmation; the phone uses native dialogs.
  12. Connection in plain words. "Round trip 42 ms" replaces "typing echo / reconnects". Inventory 6: developer copy on user screens.
  13. Reduced motion respected. Pulses and sheet slides are cut when the OS asks for it.

Known gaps

  1. Pairing, setup and the legacy PWA are not designed here.
  2. Only 6 of the 16 classifier states appear (needs, error, thinking, running, writing, idle).
  3. Not shown: size-claim and nudge behaviour, hidden-input mode, Ctrl latch, install and update notices.
  4. Close agent and Unpair are demo-only; nothing is stopped or revoked.
  5. Layout checked by reading the markup and running a syntax check; not screenshot-tested on a device.
